# 技术架构

## 1. 总体结构

知澜智慧校园采用前后端同仓库、单进程部署结构：

```text
浏览器
  ├─ React 页面与交互
  ├─ 类型化 REST 客户端
  └─ HttpOnly Cookie 会话
        │
        ▼
Node.js HTTP 服务
  ├─ 认证、Origin 校验、角色与课程归属检查
  ├─ 课程、作业、考勤、通知、任务、学情与 AI API
  ├─ AI 适配器
  └─ 生产静态资源
        │
        ├─ SQLite 持久化文件
        └─ OpenAI-compatible 模型服务（可选）
```

开发模式使用 Vite `5174`，API 在 `5175`。生产模式由 Node 在 `5175` 同时提供 API 与 `dist` 静态文件。

## 2. 前端

### 状态管理

- `App.tsx` 管理当前用户、页面视图、课程上下文、工作台数据和 Toast。
- 页面内部状态只处理本页加载、筛选与弹窗。
- 角色切换通过同一应用外壳动态替换导航文案，不依赖两个重复站点。

### 页面

| 页面 | 学生 | 教师 |
| --- | --- | --- |
| 工作台 | 学习节奏、任务、待交作业、AI 建议 | 教学概览、待批改、签到、班级分析 |
| 课程 | 课程进度、作业、公告、本人考勤 | 课程创建、学生加入、名册和课程数据 |
| 作业 | 查看要求、提交、修改、评分反馈 | 发布、查看提交、逐份批改与通知 |
| AI | 课程上下文学习答疑 | 教学诊断、反馈草稿和教学建议 |
| 考勤 | 输入签到码、查看历史 | 发起签到、复制签到码、查看名单 |
| 学情 | 个人趋势、掌握度、成绩与出勤 | 班级成绩分布、风险学生、作业表现 |
| 通知 | 搜索、筛选、查看详情 | 发布校园或课程通知 |

### 可访问性

- 主要导航、按钮、弹窗和状态提示提供语义标签。
- 弹窗支持 Escape 关闭并锁定背景滚动。
- 搜索支持 `Ctrl/Cmd + K`，AI 编辑框支持 `Ctrl/Cmd + Enter`。
- 响应式布局覆盖 1440、820 和 560 像素断点。
- 动画遵循 `prefers-reduced-motion`。

## 3. 后端

### 路由模块

- `/api/auth/*`：登录、注册、退出、会话恢复。
- `/api/courses/*`：课程列表、详情、创建与添加学生。
- `/api/assignments/*`：作业发布、提交和提交列表。
- `/api/submissions/*`：教师评分与反馈。
- `/api/attendance/*`：签到场次、学生签到和教师名单。
- `/api/announcements/*`：公告发布和用户可见范围。
- `/api/notifications/*`：站内通知和已读状态。
- `/api/analytics`：学生个人学情或教师班级学情。
- `/api/ai/*`：AI 状态、会话、对话和删除。
- `/api/profile/*`：资料与密码。
- `/api/export/courses.csv`：按角色输出真实课程数据。

### 权限规则

- 未认证访问业务 API 返回 `401`。
- 学生调用教师接口返回 `403`。
- 教师只能操作自己创建的课程、作业、提交、签到和通知。
- 学生只能提交已选课程中的作业，只能对已选课程签到。
- 评分后学生不能继续修改该作业。

## 4. 数据模型

主要实体：

- `users`：学生、教师、账号、密码哈希与基本资料。
- `sessions`：只保存会话令牌摘要和过期时间。
- `courses` / `enrollments`：课程与选课关系、进度和成绩。
- `assignments` / `submissions`：作业、最新提交、评分与反馈。
- `attendance_sessions` / `attendance_records`：签到场次与出勤记录。
- `announcements` / `notifications`：公开公告与用户站内通知。
- `tasks`：个人计划。
- `study_records`：学习时长和正确率趋势。
- `ai_conversations` / `ai_messages`：AI 会话和消息持久化。

所有表通过外键关联，数据库启用 `PRAGMA foreign_keys = ON`、WAL 和忙等待。

## 5. AI 设计

### 远程模型

环境变量配置后，后端以 OpenAI-compatible `/chat/completions` 协议调用模型。系统提示中只拼接当前用户有权访问的课程、作业与汇总指标，并明确禁止伪造学生数据。

### 本地回退

未配置密钥或远程调用失败时，使用可解释的教学规则引擎。回答围绕学习计划、条件概率、贝叶斯、评分反馈和班级分析生成。界面始终显示真实提供方，不将本地规则回答标记为远程模型。

### 会话持久化

用户消息和助手回复都保存到数据库。刷新页面或重新登录后仍可读取历史会话，可删除自己的会话。

## 6. 测试策略

- API 测试使用真实 HTTP 请求和独立随机 SQLite 数据库。
- 浏览器测试使用真实 Edge 页面，执行表单填写、按钮点击、文件下载触发和页面导航。
- 截图覆盖登录、学生全模块、教师全模块与移动端。
- 测试失败时保留测试数据库和截图，便于追踪。

## 7. 扩展建议

1. 将 SQLite 迁移到 PostgreSQL，并增加 Redis 会话与任务队列。
2. 增加对象存储、作业附件、视频课程和内容安全审核。
3. 将学习记录与知识点关系拆成知识图谱，支持真正的前置知识推荐。
4. 接入学校统一身份认证、教务系统和消息渠道。
5. 为 AI 增加可审计工具调用，但成绩修改等高风险动作必须二次确认。
