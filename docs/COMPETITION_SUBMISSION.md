## 一、项目详情

### 1. 项目名称

知澜智慧校园：AI 驱动的学生与教师一体化学习平台

### 2. 项目定位

知澜智慧校园面向高校课程教学场景，将 AI 助教、课程、作业、课堂考勤、学情分析与校园通知整合为一条可运行的业务链。平台不是静态展示页，而是包含真实认证、数据库持久化、权限隔离和跨角色协作的教学应用。

### 3. 解决的问题

- 学生需要在多个入口之间切换课程、作业、签到和通知，学习反馈分散。
- 教师难以及时看到提交进度、出勤、课程进度和潜在风险学生。
- 通用 AI 聊天缺少课程与任务上下文，回答难以落地到具体学习行动。
- 通知、评分与考勤状态不能形成闭环，纸质或表格流程反馈滞后。

### 4. 用户角色

- 学生：查看学习工作台、课程、作业、考勤、学情与通知；提交作业；向 AI 提问；管理个人任务。
- 教师：创建课程、添加学生、发布作业、批改反馈、发布签到、查看班级学情和发布通知。

## 二、使用方式

### 1. 学生流程

1. 使用学号 `2024001`、密码 `Campus@2026` 登录。
2. 在工作台查看待完成作业、进行中的签到和近 14 天学习趋势。
3. 进入课程查看进度、公告、作业与本人历史考勤。
4. 在作业中心提交或修改文本作答；评分后只能查看反馈。
5. 在考勤页输入教师现场公布的签到码。
6. 在 AI 助理选择课程上下文，提问或点击真实建议问题。
7. 在学情分析查看成绩、出勤、课程掌握度和近 14 天学习投入。

### 2. 教师流程

1. 使用工号 `T1001`、密码 `Teacher@2026` 登录。
2. 在工作台查看课程、学生、待批改和班级平均数据。
3. 在课程管理创建课程或通过学号添加学生。
4. 发布作业并设置截止时间和满分。
5. 打开学生提交，逐份评分和填写反馈；学生收到站内通知。
6. 发起课堂签到，给出现场签到码，查看实时名单。
7. 在班级学情查看分数分布、需关注学生、作业表现并导出 CSV。
8. 发布全校或课程范围通知。

## 三、项目亮点

1. **双角色业务闭环**：从登录、课程、作业、评分、通知到考勤与分析，所有角色动作写入同一业务数据库。
2. **真实 AI 上下文**：AI 回答可以关联当前课程、作业和学情；会话、用户消息和助手回答均持久化。
3. **不伪造 AI 状态**：配置远程模型时显示模型名称；未配置时明确使用本地教学引擎；远程异常时提示并回退。
4. **可核验的课堂签到**：签到码有数字格式、关闭时间、课程选课关系、错误码和重复签到校验。
5. **数据驱动教学**：教师看到班级分数结构、风险学生、作业完成率和出勤率；学生看到自己的课程进度和学习趋势。
6. **完整权限与安全设计**：scrypt 密码哈希、HttpOnly Cookie 会话、参数化 SQL、Origin 校验、教师课程归属检查。
7. **移动端可用**：导航、统计、课程、签到和学情在手机宽度下重新排版，无假按钮和空点击。

## 五、关键技术

### 1. 前端

- React 18 组件化页面与 TypeScript 严格类型。
- Vite 5 开发和生产构建。
- 动态角色导航、全局搜索、通知抽屉、可访问弹窗、Toast 和响应式 CSS。
- 非阻塞数据加载、错误反馈、空状态、表单校验和复用组件。

### 2. 后端

- Node.js 原生 HTTP REST API。
- SQLite `node:sqlite`，启用外键、WAL 和参数绑定。
- scrypt 加盐密码哈希、SHA-256 会话摘要、HttpOnly Cookie。
- 服务端角色检查和课程归属检查，前端隐藏按钮不作为安全边界。
- 登录频率限制、Origin 校验、请求体大小限制和统一安全响应头。

### 3. AI

- 支持 OpenAI-compatible `/chat/completions` 接口。
- 通过环境变量配置 Base URL、模型和密钥。
- 服务端拼接用户有权访问的课程与学情上下文。
- 本地教学引擎用于无密钥演示和远程故障回退。

### 4. 数据与测试

- 课程、选课、作业、提交、评分、签到、通知、任务、学习记录和 AI 会话均落库。
- Node Test Runner 执行真实 HTTP 回归。
- Playwright + Microsoft Edge 执行学生/教师真实页面流程和截图验收。

## 六、创意与原创性说明

- 产品将“AI 助教”放在完整教学业务闭环中，而不是独立聊天窗口。
- AI 页面同时对学生和教师提供不同任务导向，并显示真实模型来源。
- 课堂签到、作业反馈、通知与学情分析共享同一数据来源，避免页面间数据割裂。
- 视觉上使用校园教育语义、清晰的信息层级和低噪声数据界面，不采用营销落地页式结构。

项目代码为独立实现。调研阶段参考了智慧校园产品的常见业务结构，例如课程、作业、考勤、通知和角色隔离；未复制参考开源项目的代码。提交表如要求说明前期基础，可如实填写：“由团队早期同主题原型重构，前端、认证、数据模型和业务接口均重新实现”。

当前仓库未包含公开发表或获奖记录。提交前请参赛者按实际情况填写是否发表、获奖或存在二次优化。

## 七、商业价值与可行性

### 1. 目标客户

- 高校教务处、二级学院和课程教学团队。
- 高职高专与职业培训机构。
- 需要私有化部署和数据可控的教育机构。

### 2. 核心付费模式

- SaaS 订阅：按院系、课程或活跃学生数收费。
- 私有化部署：收取一次性部署、迁移和培训费用。
- AI 增强包：按模型调用量或年度服务包计费。
- 数据服务：在合规授权下提供课程质量报告和教学分析。

### 3. 成本结构

- 云主机、持久磁盘、带宽和数据库。
- 大模型调用费用。
- 学校系统对接、实施培训和运维支持。
- 内容安全、隐私合规与安全审计。

### 4. 市场进入策略

1. 选择 1-2 门课程做 4 周试点，免费或低价部署。
2. 与授课教师共同定义作业、签到和学情指标。
3. 用出勤率、作业完成率、反馈周期和教师节省时间形成试点报告。
4. 从课程推广到专业，再推广到二级学院。
5. 与学校统一身份认证和教务系统集成，提高替换成本和使用黏性。

### 5. 可行性依据

- 不依赖外部数据库，单实例即可完成演示和试点。
- 前端、后端、数据库、AI 适配器均由同一技术栈维护，部署成本低。
- SQLite 可支持中小规模课程试点，后续可迁移 PostgreSQL。
- AI 无密钥也能运行本地教学引擎，避免演示现场因费用或网络完全中断。

## 八、上线运营能力

### 1. 上线计划

- D-7：准备生产域名、HTTPS、模型密钥和持久磁盘。
- D-3：导入试点院系、课程、教师和学生数据。
- D-1：执行 API、浏览器、权限和移动端回归。
- D 日：教师培训 30 分钟，学生使用说明 5 分钟。
- D+7：检查登录、签到、作业和 AI 使用数据，修复高频问题。
- D+30：输出试点数据报告，确定扩容方案。

### 2. 运维计划

- `/api/health` 用于服务健康检查。
- 每日备份 SQLite 文件和 WAL 状态。
- 每周清理过期会话和检查错误日志。
- 每月更新依赖、检查模型成本和安全配置。
- 关键更新前在独立测试数据库执行 API 与 E2E 回归。

### 3. 用户反馈机制

- 教师每周反馈作业和考勤流程阻力。
- 学生通过课程反馈与行为数据发现使用断点。
- 以登录完成率、作业提交率、课堂签到率、AI 对话完成率和 7 日留存作为核心指标。
- 建立问题分级：阻断教学、影响效率、体验优化。

### 4. 合规与风险控制

- 遵循最小必要原则，不收集与教学无关的个人信息。
- 生产环境使用 HTTPS，设置强邀请码并更换演示密码。
- AI 仅提供建议，不直接修改成绩、考勤或处分数据。
- 接入学校前完成隐私政策、数据授权、日志留存和模型服务合规审查。
- 第三方模型密钥不得提交到源码或网盘公开目录。
